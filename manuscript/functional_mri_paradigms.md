# Functional MRI paradigms

*(Scientific Data — Methods / Data Descriptor wording. Intended to answer: if a user downloads this dataset in five years, can they understand exactly what was acquired and how to model it without reading laboratory MATLAB?)*

The dataset includes four complementary blood-oxygen-level-dependent (BOLD) functional MRI paradigms: (i) resting-state fixation (`task-rest`); (ii) monocular naturalistic movie stimulation (`task-movie`); (iii) block-design visual stimulation with grating and checkerboard stimuli (`task-fmri`); and (iv) short control functional acquisitions (`task-control`). These paradigms were designed to characterise spontaneous functional organisation and stimulus-evoked responses within the visual system under monocular viewing conditions. Sequence parameters common to all BOLD series (TR 937 ms, TE 37 ms, flip angle 52°, 2 mm isotropic voxels, multiband acceleration factor 8) are recorded in each `*_bold.json` sidecar and summarised in **Table X** (`Table1_Functional_paradigm_summary`; see also overview **Figure Xa** / `Figure2_functional_paradigm_overview`). The subsections below describe each paradigm and the stimulus-related metadata included in the public release. Together, these paradigms provide complementary measurements of spontaneous functional connectivity, naturalistic visual processing, and visually evoked cortical responses, enabling multimodal investigation of functional reorganisation following optic nerve injury.

## Resting-state fixation

Resting-state BOLD data were acquired under the BIDS task label `task-rest`. Participants viewed a uniform grey background with a central white fixation cross. Visual fixation was monocular: the non-stimulated eye remained occluded (dark), and no stimulus blocks were presented. Each resting-state run comprised 320 BOLD volumes (approximately 5 minutes at the shared functional TR). No task event tables are released for this paradigm (no events by design). When available, colocated BIDS physiology files (`recording-pulse`, `recording-respiratory`, `recording-trigger`) provide cardiac, respiratory, and trigger traces for confound modelling and synchronisation checks.

## Naturalistic movie viewing

Naturalistic movie-viewing fMRI was acquired under the BIDS task label `task-movie` as four magnitude functional runs per complete session, corresponding to movie segments Movie1A, Movie2A, Movie1B, and Movie2B (scanner `ProtocolName` families `Movie1`–`Movie4`). Monocular eye assignment under the default laboratory setting was: Movie1 / Movie1A, left eye; Movie2 / Movie2A, right eye; Movie3 / Movie1B, right eye; Movie4 / Movie2B, left eye (**Table Y** / `Table2_Movie_run_eye_assignment`; machine-readable maps in `code/task-movie/`). A fixation cross was superimposed during movie presentation. Each complete movie run comprised 210 BOLD volumes (approximately 3.3 minutes; ~196.77 s at TR = 0.937 s).

Design-level `*_events.tsv` files are included for **all** magnitude `task-movie` runs. Columns include `onset`, `duration`, `trial_type` (`movie`), `stim_file`, `eye`, `movie_label`, and `matlab_run_id` (definitions in `task-movie_events.json`). Timing uses `onset = 0` under the laboratory-confirmed assumption that scanner acquisition and clip playback started together, with `duration` equal to the measured MP4 length (196.821333 s) or capped to `n_volumes × TR` for truncated runs. These events support run-level / continuous-movie analyses; they are not millisecond TTL-locked onsets because movie presentation scripts did not save trigger timestamps. Movie video files are not redistributed because of copyright restrictions. Documentation sufficient for reuse without MATLAB is provided in `code/task-movie/README.md`.

## Block-design visual stimulation

Visually driven task BOLD data were acquired under the BIDS task label `task-fmri` using a block-design grating and checkerboard stimulation paradigm synchronised to MRI scanner triggers (**Figure Xb** / `Figure1_task_fmri_block_design`). After an initial baseline of 10 TRs, the experimental design comprised 12 cycles of 8 TR stimulus presentation alternating with 10 TR baseline periods, for a total of 226 BOLD volumes per run. Twelve stimulus conditions (`stim-01` to `stim-12`) encompassed magnocellular and parvocellular polar-checkerboard variants (drifting vs contrast-flickering; square-wave vs sine-wave; black–white vs red–green isoluminant). Conditions `stim-07`…`stim-12` are intentional within-run repeats of `stim-01`…`stim-06`. During presentation, a fixation marker consisting of a blue/red oval with a central cross was displayed. Stimulus order was randomised across subjects.

Event timing files (`*_events.tsv`; **514** runs) provide `onset`, `duration`, and `trial_type` (`baseline` or `stim-01`…`stim-12`). Onsets were reconstructed from measured scanner trigger recordings (MATLAB `scan_info` / `triggerTimes`) combined with stimulus-order metadata when a unique protocol→BOLD correspondence could be established; no default TR was substituted and no synthetic onsets were invented for unmatched runs. A complete machine-readable mapping between `stim-XX` identifiers and stimulus parameters (pathway, spatial frequency, drift/flicker rates, contrast, colour mode, MATLAB renderer) is provided in `code/task-fmri_condition_dictionary.tsv`, with column definitions in `code/task-fmri_condition_dictionary.json` and human-readable levels in dataset-root `task-fmri_events.json`. The canonical block-design source file `code/presentStimParams.m` is released for provenance. Users can therefore build first-level models from BIDS events + the condition dictionary without executing laboratory code.

## Control functional acquisition

Short control functional runs were acquired under the BIDS task label `task-control`. Each control run comprised 20 BOLD volumes (approximately 19 seconds) using the same EPI prescription as the other functional paradigms (phase-encode direction may be AP or PA depending on the Control1–3 series). The exact stimulus content of these control runs could not be fully reconstructed from the available documentation (no dedicated control paradigm script identified in the audited MATLAB folders). No `*_events.tsv` files are released for control. Physiology files are available for a subset of control runs when PhysioLog conversion succeeded.

## Physiology acquired with functional runs

Where Siemens PhysioLog conversion passed release gates, BIDS physiology files are colocated with the corresponding BOLD run (`recording-pulse`, `recording-respiratory`, `recording-trigger`, and rarely `recording-ecg`). Sidecars specify sampling frequency, `StartTime` relative to BOLD onset, and start-time confidence. Session-wide peripheral PMU logs and eye-tracking time series are **not** included in the present BIDS release.
